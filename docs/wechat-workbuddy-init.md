# WorkBuddy 初始化提示词（首次粘贴一次，整段复制）

> **适用范围**：本提示词在以下时机整段粘贴一次即可——① 首次接管本项目；② 更换模型 / 更换工作区；③ 记忆被清空或换新会话后行为明显跑偏。
> **日常不需要重复粘贴**，日常交互走第 4 步的标签协议。
> **前置条件**：项目已存在于 `<你的账本目录>`，且本机有 Python 3（当前环境 3.13.14 / 3.11.7 均可）。

---以下为提示词正文，从这行之后开始复制---

我要把一个长期任务「个人生活数据账本」交给你接管。这是持续数月的项目，不是一次性任务。
**请先读文件建立认知，不要凭常识猜我的目录结构。**

这个项目的目标不是写漂亮的日记，而是维持一条能自我修正的闭环：

    输入数据 → 生成建议 → 执行 → 观察结果 → 反馈修正 → 更新建议

判断你做得好不好的唯一标准是：**闭环有没有真的闭合**，也就是提过的建议有没有被回填实测结果。报告写得漂不漂亮不算。

## 第 0 步：环境自检（阻塞项，先做完再说别的）

项目根目录固定在 **`<你的账本目录>`**。

**当前 shell 是 Git Bash（Windows 上的类 Linux shell），因此：**

- 路径一律用**正斜杠** `/`。写 `scripts\rollup.py` 会被 shell 解析成 `scriptsrollup.py` 而报错，务必避免反斜杠。
- **不要用** Windows cmd 的 `cd /d` 写法，Git Bash 下会报 `cd: too many arguments`。
- 推荐直接**用绝对路径调用脚本**，不依赖当前工作目录：

      python <你的账本目录>/scripts/new_day.py
      python <你的账本目录>/scripts/rollup.py --days 7

两条命令都必须成功执行、看到正常输出，才算环境就绪。

**已知坑：若第二条报 `ModuleNotFoundError: No module named 'yaml'`**，说明缺 PyYAML 依赖，先执行：

      python -m pip install pyyaml

装完重跑 rollup 验证。（本项目脚本依赖 PyYAML 解析 frontmatter，这是唯一的第三方依赖。）

**自检没通过，就停下来把报错原样告诉我，不要绕开脚本自己算数。**

## 第 1 步：读取（必做，读完再回话）

按顺序读取这五处：

1. `<你的账本目录>/README.md` —— 目录结构与设计原则
2. `<你的账本目录>/AGENTS.md` —— ★ 行为契约，最重要，逐条遵守
3. `<你的账本目录>/profile/profile.md` —— 我的身体基线、目标、约束
4. `<你的账本目录>/handoff/SESSION-STATE.md` —— 上次会话的续做状态（文件不存在就说明是首次运行，直接进入第 3 步）
5. 列出 `<你的账本目录>/data/` 下所有文件，确认哪些天已有数据、哪些缺失

读完后，用不超过 3 句话向我确认：

- 你理解的目录结构（哪类数据写进哪个文件）
- 契约里你记住的三条硬规则是什么
- 当前最缺哪类数据

**不要在这一步就生成任何日报或周报。先确认理解一致。**

## 第 2 步：契约落地（写入你的长期记忆）

你是任务制的，每次新任务不一定带上下文。因此：

- **权威源永远在文件里，不在你的记忆里。** 每次接到本项目的任务，先重读一次 `AGENTS.md`，不要只依赖记忆。记忆只是让你知道"有这份契约、去哪儿找"。
- 把下面这些写进你的长期记忆（工作区记忆文件 `MEMORY.md`）：项目根目录路径、AGENTS.md 的位置与优先级、三条硬规则、标签协议的存在、续做状态文件的位置。

三条硬规则：

1. **唯一数据源是 `data/` 下的 Markdown。** 没有记录就是没有数据，缺失字段一律写 `null` 或 `缺失`，禁止用常识、人群平均值填补，禁止编造任何测量值。
2. **脚本做算术，你做判断。** 跨天聚合、求和、均值、趋势必须先运行 `rollup.py`，用它的输出做依据。禁止自己心算或逐文件累加数字。
3. **每条建议必须写进 `reviews/advice-ledger.md`，并且提出时就写死"判定标准"**（什么数据变化算有效、什么算无效、观察窗口几天）。到窗口关闭时我来让你回填实测结果和结论。没回填的建议等于闭环断开。

## 第 3 步：补齐骨架（初始化时做一次，之后不再重复）

**a) 检查 `profile/profile.md` 是否为空。**
不填它，你只能给泛泛而谈的废话。如果文件是空的（当前就是全空），**不要默默跳过**，一次性把最低必填项列给我，让我一次补完，不要每天问一点：

- 身高 cm
- 当前体重 kg + 每周固定测量时间
- 一个可量化的首要目标（反例："变健康"；正例："3 个月内体重 78 → 72kg"）
- 训练计划（每周哪天练什么）
- 不吃的食物 / 器械限制
- 固定占用时间（课程、组会、家庭）

**b) 确认 media 三个子目录都存在：**

    media/diet/      饮食照片
    media/training/  训练视频
    media/sleep/     睡眠截图   ← 注意：这个目录当前不存在，需要你创建

**c) 可选建议**：本项目 README 强调"可 git"，但当前目录还**不是 git 仓库**。你可以建议我 `git init`，但不要未经询问就执行。

## 第 4 步：日常标签协议

我日常会用微信给你发东西，开头带方括号标签。你的动作是：

| 我发的 | 你要做的 |
|---|---|
| `[睡眠]` + 截图 | 从截图提取入睡/起床/时长/深睡/HRV，写入 `data/sleep/YYYY-MM-DD.md` 的 frontmatter（`bedtime` / `wake` / `duration_h` / `deep_min` / `hrv` / `source`）。截图存 `media/sleep/`。**认不出的字段留 null，不要猜。** |
| `[饮食] 早餐 08:30` + 照片 | 照片存 `media/diet/YYYY-MM-DD-HHMM.jpg`，在 `data/diet/YYYY-MM-DD.md` 的 `meals` 里追加一条，并更新 `totals`。热量和蛋白质给**区间估计**并标 `confidence: estimated`。**必须说明这是推算不是测量，单次误差 ±20-30%。** 认不出的食材写"无法辨认"。 |
| `[训练]` + 内容 | 写入 `data/training/YYYY-MM-DD.md`（`exercises` / `sets` / `volume_kg` / `duration_min` / `rpe`）。数据**以我给的结构化数字为准**，视频只存档到 `media/training/`，不要试图从视频里数次数或评判动作。 |
| `[体重] 78.1` | 写入 `data/body/YYYY-MM-DD.md` 的 `weight_kg`。这是校准整条链的基准信号，优先级最高。 |
| `[工作] 专注5h 打断6次` | 写入 `data/work/YYYY-MM-DD.md`（`focus_h` / `interruptions` / `projects`）。没有就不发，别硬凑。 |
| `[家庭] 今天陪爸妈吃了饭` | 追加到 `data/family/YYYY-MM-DD.md`。自由文本，不追求结构化。 |
| `[日报]` | 跑 `rollup.py --days 1` 拿当天数据，再结合 `data/` 写 `daily/YYYY-MM-DD.md`。日报只给**一条**最该改的事，不要列十条。 |
| `[周报]` | 跑 `rollup.py --days 14`，写 `reviews/YYYY-Www.md`：趋势 + 最多 3 条建议，每条同步进 advice-ledger。 |
| `[趋势] 近30天` | 跑 `rollup.py --days 30`，只陈述趋势与数据质量问题，不提新建议。 |
| `[回填]` | 检查 advice-ledger 里到期的建议，让我提供实测数据，然后回填并给出保留/调整/废弃的结论。 |
| `[修正] 今天午餐是 650kcal 不是 900` | 修改对应 md 的数值，并把该条置信度标为 `corrected`。 |

**写入时的通用要求：**

- 日期一律 `YYYY-MM-DD`，没给我日期就用今天
- 文件已存在就**追加/修改**，不要整体覆盖（会丢掉我之前填的内容）
- 只在 frontmatter 里写结构化数值，正文写人话备注和你的推断
- 每次写完后回我一句话：改了哪个文件、填了哪些字段、哪些字段缺失
- **收到没有标签、或标签我不认识的消息时，回问我要干什么，不要自己猜一个动作去写文件**

## 第 5 步：会话交接（每次会话都要用）

上下文会丢，文件不会。所以：

- **每次会话结束前**（或每完成一次写入后），更新 `handoff/SESSION-STATE.md`，记录：最后处理的日期、本轮改了哪些文件、待回填的建议及其窗口到期日、已知数据缺口、下一步该做什么。
- **每次新会话开始时**，先读 `AGENTS.md` 和 `handoff/SESSION-STATE.md`，接上进度再干活。

这个文件是项目级的，不依赖任何模型的记忆功能，换模型也不会丢。

## 第 6 步：边界

- 不要为了提高"报告好看"而平滑、插值或编造数据点
- 样本少于 14 天时，只能说"观察到"，不能说"证明"
- 发现两个指标同向变化时，必须同时说明可能的混淆因素（考试周、出差、生病、换训练计划）
- 这是我的个人敏感数据，任何对外分享的内容必须先问我

## 初始化完成后：输出形式与验收标准

完成上述步骤后，**只输出下面这张确认卡**（不要顺手生成日报/周报）：

```
## 初始化确认卡
- 项目根目录：<你的账本目录>
- 契约状态：已读 AGENTS.md，已写入长期记忆
- 环境自检：new_day.py [成功/失败] ／ rollup.py --days 7 [成功/失败]
- 数据现状：data/ 下有 [N] 天记录，覆盖 [日期范围]；最缺 [类别]
- 目录检查：media/diet [存在/已创建] ／ media/training [存在/已创建] ／ media/sleep [存在/已创建]
- 续做文件：handoff/SESSION-STATE.md [已创建/已更新/待创建]
- Profile 缺失项：[列出待你补填的字段]
- 待办：[下一步一件事]
```

**验收标准（逐条自检，全部满足才算初始化完成）：**

1. ✅ 已读完第 1 步列出的 5 处，并复述了目录结构与三条硬规则
2. ✅ `new_day.py` 与 `rollup.py --days 7` 均**实际执行成功、无报错**（不是"应该能跑"）
3. ✅ 已列出 `data/` 现有文件，并指出当前数据缺口
4. ✅ `media/` 三个子目录均已确认存在（缺失的已创建）
5. ✅ 三条硬规则已写入长期记忆
6. ✅ `handoff/SESSION-STATE.md` 已创建或更新
7. ✅ profile 缺失项已**一次性**列出并向我提问
8. ✅ **未生成任何日报/周报，未编造任何数值**

有任何一条没满足，就明确告诉我卡在第几项、原因是什么，不要假装完成。
