# 建议台账

> 这是整个系统的核心。提出建议只是开始，**回填结果才是闭环**。
> 一条没有回填「实测变化」的建议，等于没提。

## 字段说明

| 字段 | 含义 |
|---|---|
| 提出日期 | 建议写入的日期 |
| 建议 | 一句话，可执行 |
| 依据指标 | 触发这条建议的数据（写具体数值） |
| 采纳 | 是 / 部分 / 否（没执行也要记，这是重要信息） |
| 观察窗口 | 通常 7-14 天，写起止日期 |
| 判定标准 | 什么变化算有效，什么算无效（**提建议时就要写，不能事后编**） |
| 实测变化 | 窗口结束后的真实数据 |
| 结论 | 保留 / 调整 / 废弃 |

## 台账

| 提出日期 | 建议 | 依据指标 | 采纳 | 观察窗口 | 判定标准 | 实测变化 | 结论 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

## 复盘规则

每 4 周统计一次「采纳率」和「有效率」。

- 采纳率低 → 建议不切实际，要降低执行门槛，**不是使用者的问题**
- 采纳率高但有效率低 → 依据指标选错了，或因果假设本身有问题
